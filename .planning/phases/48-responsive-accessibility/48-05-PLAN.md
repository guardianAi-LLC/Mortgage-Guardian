<task type="auto">
  <name>Task 1: ARIA live regions and form validation accessibility</name>
  <files>frontend/src/components/global-search.tsx, frontend/src/components/case-form.tsx, frontend/src/app/dashboard/documents/page.tsx</files>
  <action>
1. global-search.tsx:
   - Add `aria-live="polite"` to the search results dropdown container so screen readers announce results as they appear.
   - Add `role="listbox"` to the results list container and `role="option"` to each result item.
   - Add a visually hidden status message: when loading show "Searching...", when results arrive show "{n} results found", when empty show "No results". Use `<span className="sr-only" aria-live="polite">{statusMessage}</span>`.

2. case-form.tsx:
   - On form fields that fail validation, add `aria-invalid={!!error}` and `aria-describedby={errorId}` pointing to the error message element.
   - Error messages should have `id={errorId}` and `role="alert"` so screen readers announce them immediately.
   - If the form already has error handling, wire aria-invalid into it. If not, add the attributes so they're ready when validation is added.

3. documents/page.tsx:
   - If document list shows a "processing" status that auto-updates (from smart polling), wrap the status area in `aria-live="polite"` so screen readers announce when documents complete processing.
   - Add `aria-busy={isLoading}` to the table container when data is being fetched.
  </action>
  <verify>Run `cd frontend && npx next build` — build succeeds. Grep for "aria-live" and "aria-invalid" in modified files.</verify>
  <done>Search results announced to screen readers. Form errors announced on validation failure. Document processing status changes announced. aria-busy on loading tables.</done>
