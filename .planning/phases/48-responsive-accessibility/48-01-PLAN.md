<task type="auto">
  <name>Task 1: Skip-to-content link and aria-current on sidebar navigation</name>
  <files>frontend/src/components/app-shell.tsx, frontend/src/components/sidebar.tsx</files>
  <action>
1. In app-shell.tsx, add a visually-hidden skip link as the FIRST child inside the outer div:
   `<a href="#main-content" className="sr-only focus:not-sr-only focus:absolute focus:z-50 focus:top-2 focus:left-2 focus:bg-blue-600 focus:text-white focus:px-4 focus:py-2 focus:rounded-md">Skip to content</a>`
   Add `id="main-content"` to the `<main>` element.

2. In app-shell.tsx, add `aria-label="Open navigation menu"` to the hamburger Button (the one wrapping the Menu icon).

3. In sidebar.tsx, add `aria-current={isActive ? 'page' : undefined}` to each nav Link element. This tells screen readers which page is active.

4. In sidebar.tsx, add `aria-label` to the processing badge span: `aria-label={`${processingCount} documents processing`}`.
  </action>
  <verify>Run `cd frontend && npx next build` — build succeeds. Grep for "skip" and "aria-current" in the modified files to confirm presence.</verify>
  <done>Skip-to-content link renders (visible on Tab focus), aria-current="page" on active nav link, aria-label on hamburger button and processing badge.</done>
</task>

<task type="auto">
  <name>Task 2: Aria-labels on icon-only buttons across components</name>
  <files>frontend/src/components/global-search.tsx, frontend/src/app/dashboard/documents/page.tsx, frontend/src/app/dashboard/bank-accounts/page.tsx, frontend/src/app/dashboard/documents/[documentId]/page.tsx</files>
  <action>
Audit all icon-only buttons (buttons with only an icon child, no visible text) and add aria-label attributes:

1. global-search.tsx: The search trigger button (if icon-only) needs `aria-label="Search (Cmd+K)"`. The close/clear button needs `aria-label="Clear search"`.

2. Documents page: Any icon-only action buttons (delete, re-analyze) in batch action bar need aria-labels like `aria-label="Delete selected"`, `aria-label="Re-analyze selected"`.

3. Document detail page: Action buttons need labels — `aria-label="Re-analyze document"`, `aria-label="Delete document"`.

4. Bank accounts page: Unlink buttons, expand/collapse toggles need `aria-label="Unlink account"`, `aria-label="Expand account details"` / `aria-label="Collapse account details"`.

5. Any pagination buttons across pages: add `aria-label="Previous page"` and `aria-label="Next page"`.

Do NOT add aria-labels to buttons that already have visible text content — only icon-only buttons.
  </action>
  <verify>Run `cd frontend && npx next build` — build succeeds. Grep for `aria-label` in modified files to confirm additions.</verify>
  <done>All icon-only buttons have descriptive aria-labels. No button exists with only an icon and no accessible name.</done>
</task>

<task type="auto">
  <name>Task 3: RiskBadge SR-only icons for non-color-only status</name>
  <files>frontend/src/components/risk-badge.tsx</files>
  <action>
Add a small SR-only icon prefix to each risk level so status isn't conveyed by color alone (WCAG 1.4.1 Use of Color):

1. Import `CircleAlert, AlertTriangle, Info, ShieldCheck, Circle` from lucide-react.
2. Add a `levelIcons` map: critical→CircleAlert, high→AlertTriangle, medium→AlertTriangle, low→Info, clean→ShieldCheck, info→Circle.
3. Render the icon BEFORE the label text inside the Badge: `<Icon className="h-3 w-3 mr-1" aria-hidden="true" />`.
4. The icon is visual reinforcement (aria-hidden since the text label already conveys meaning).

This ensures sighted users have both color AND icon to distinguish severity levels, meeting WCAG 2.1 AA 1.4.1.
  </action>
  <verify>Run `cd frontend && npx next build` — build succeeds. Visually: risk badges now show a small icon before the text label.</verify>
  <done>RiskBadge renders icon+color+text for all 6 risk levels. Color is not the sole distinguisher.</done>
</task>
