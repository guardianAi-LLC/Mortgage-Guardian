Create `frontend/e2e/error-states.spec.ts` — requires authentication.

Use `page.route()` to simulate different API states.

Empty states:
1. "dashboard shows empty state when no cases" — intercept /api/v1/cases with empty array, verify empty state message and CTA
2. "documents page shows empty state" — intercept /api/v1/documents with empty array, verify empty state
3. "analytics shows empty state" — intercept analytics with zero data, verify empty state

Loading states:
4. "dashboard shows loading skeleton" — delay API response by 2s, verify skeleton/spinner appears before data loads
5. "documents page shows loading skeleton" — same pattern for documents

Error states:
6. "dashboard handles API error gracefully" — intercept /api/v1/cases with 500 status, verify error message displayed (not blank page)
7. "documents page handles API error" — intercept with 500, verify error state
8. "document detail handles 404" — intercept with 404, verify "not found" message

Network failure:
9. "handles network failure" — abort API requests, verify error boundary or error message

For each state test:
