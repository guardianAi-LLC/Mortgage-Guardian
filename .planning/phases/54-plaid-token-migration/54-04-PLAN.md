<task type="auto">
  <name>Task 2: Write the backfill script (idempotent, dry-run by default)</name>
  <files>backend-express/scripts/backfill-plaid-tokens.js, backend-express/scripts/README.md</files>
  <action>
Create `backend-express/scripts/backfill-plaid-tokens.js`:

Behavior:
1. Connects to Supabase using `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` from env (NEVER the anon key).
2. Selects all `plaid_items` rows `WHERE access_token IS NOT NULL`.
3. For each row:
   - If `access_token_encrypted` is already populated: verify it decrypts to the same plaintext. On match, queue plaintext for null-out. On mismatch, log an ERROR including item_id, skip the row, and increment a `mismatch` counter — operator investigates manually.
   - If `access_token_encrypted` is NULL: encrypt the plaintext with `plaidTokenEncryptionService.encryptForStorage(user_id, access_token)`, write to `access_token_encrypted`, queue plaintext for null-out.
4. Two flags:
   - `--dry-run` (DEFAULT): logs the plan, writes NOTHING.
   - `--apply`: applies encryption writes AND nulls out plaintext for verified rows in a single transaction-like batch (Supabase doesn't expose true tx for `.update` chains — do row-by-row updates and accumulate failures into a final report).
5. Final report (always printed): `{ total, alreadyEncryptedVerified, newlyEncrypted, mismatches, errors, plaintextNulledOut }`.
6. Exit code 0 only if `mismatches === 0 && errors === 0`.

Do NOT log access_token values. Log only itemId, userId, and counts.

Update `backend-express/scripts/README.md` (create if missing) with:
- Purpose of the script
- How to run dry-run vs apply
- Rollback note: nulling out plaintext is reversible only via Plaid re-link (no plaintext backup retained — intentional)
- Reference to the runbook entry added in Task 3
  </action>
  <verify>
1. Local dev DB seeded with 3 fake `plaid_items` rows (plaintext only).
2. `node backend-express/scripts/backfill-plaid-tokens.js --dry-run` reports `newlyEncrypted: 3, plaintextNulledOut: 3 (would null)`, writes nothing.
3. `node backend-express/scripts/backfill-plaid-tokens.js --apply` updates rows: `access_token_encrypted` populated, `access_token` is NULL.
4. Re-running `--apply` is idempotent: reports `total: 0` (the `WHERE access_token IS NOT NULL` filter is empty).
5. Seed a deliberately corrupt row (plaintext "A", encrypted of "B"). Script reports `mismatches: 1` and exits 1.
  </verify>
  <done>Idempotent backfill script with dry-run default, mismatch detection, no token logging.</done>
</task>
