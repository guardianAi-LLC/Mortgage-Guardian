# Prior plan context:
@.planning/phases/50-production-deployment/50-01-SUMMARY.md

**Tech stack available:** Next.js 16.1.7, Clerk auth, Sentry, standalone output
**Established patterns:** API rewrites in next.config.ts proxy /api/v1/* to Express backend
**Constraining decisions:**
- Backend already has vercel.json for its own Vercel deployment
- Frontend uses NEXT_PUBLIC_API_URL for backend base URL (baked at build time)
- Clerk keys are build-time env vars (NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY)
- Express backend must be deployed separately (Railway or its own Vercel project)
</context>

<task type="auto">
  <name>Task 1: Frontend Vercel configuration and environment setup</name>
  <files>frontend/vercel.json, frontend/.env.production.example</files>
  <action>
1. Create `frontend/vercel.json` with:
   - framework: "nextjs"
   - buildCommand: "npm run build"
   - outputDirectory: ".next"
   - Headers: cache-control for static assets (_next/static/* → max-age=31536000, immutable), security headers matching next.config.ts
   - Rewrites: Ensure /api/v1/* proxies to the Express backend URL (this supplements next.config.ts rewrites for edge cases)

2. Create `frontend/.env.production.example` documenting all required production env vars:
   - NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY (required)
   - CLERK_SECRET_KEY (required)
   - NEXT_PUBLIC_API_URL (required — Express backend URL)
   - NEXT_PUBLIC_APP_URL (required — this Vercel deployment URL)
   - NEXT_PUBLIC_SENTRY_DSN (optional)
   - NEXT_PUBLIC_ENABLE_PLAID (optional, default false)
   - NEXT_PUBLIC_ENABLE_AI_ANALYSIS (optional, default false)

3. Verify `npm run build` succeeds in frontend/ with no errors. Check that standalone output is generated.

Do NOT create the actual Vercel project or deploy yet — that's the next task. Do NOT modify next.config.ts unless fixing a build issue.
  </action>
  <verify>
- `cd frontend && npm run build` succeeds
- frontend/vercel.json exists with valid JSON
- frontend/.env.production.example lists all required vars
  </verify>
  <done>Vercel config ready, production env vars documented, build verified</done>
</task>

<task type="auto">
  <name>Task 2: Deploy frontend to Vercel</name>
  <files>frontend/</files>
  <action>
1. From frontend/ directory, run `vercel --yes` to create Vercel project and deploy preview.
2. If auth error → stop and create checkpoint:human-action for `vercel login`.
3. Set environment variables using `vercel env add`:
   - NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY (from .env)
   - CLERK_SECRET_KEY (from .env)
   - NEXT_PUBLIC_API_URL (Express backend URL)
   - NEXT_PUBLIC_APP_URL (Vercel deployment URL — set after first deploy)
   - NEXT_PUBLIC_SENTRY_DSN (if available)
4. Trigger production deployment: `vercel --prod`
5. Capture the production URL.

If Vercel CLI is not installed, install via `npm install -g vercel` first.
If environment variables are not available in .env files, create a checkpoint:human-action to collect them.
  </action>
  <verify>
- `vercel ls` shows the deployment
- Production URL returns 200 (may redirect to Clerk sign-in)
- `curl -s <prod-url> | head -20` returns HTML
  </verify>
  <done>Frontend deployed to Vercel production with all environment variables configured</done>
</task>
