<task type="auto">
  <name>Task 1: Create useDocumentNotifications hook</name>
  <files>frontend/src/hooks/use-document-notifications.ts</files>
  <action>
  Create a new hook `useDocumentNotifications` in a dedicated file (following the pattern from use-plaid-link.ts — domain-specific hooks get their own files).

  The hook should:
  1. Accept the documents array from useDocuments as a parameter.
  2. Use a `useRef` to track the previous pipeline_status of each document (Map<string, string>).
  3. On each render (when documents change), compare current statuses to previous statuses.
  4. Fire `toast.success()` when a document transitions TO `complete` — message: `"${fileName} analysis complete"` with a description: `"View results"`.
  5. Fire `toast.error()` when a document transitions TO `failed` — message: `"${fileName} processing failed"` with a description: `"Retry or contact support"`.
  6. Update the ref with current statuses after comparison.
  7. Skip notifications on initial load (when ref is empty) — only notify on transitions.

  Import `toast` from `sonner`. Use `document.file_name` for the file name display (truncate to 40 chars if longer).

  Do NOT fire toasts for intermediate transitions (uploaded→ocr, ocr→classifying, etc.) — only terminal states. Too many toasts causes notification fatigue.
  </action>
  <verify>Read the hook file and confirm it tracks previous statuses, detects transitions, and only fires toasts for complete/failed.</verify>
  <done>useDocumentNotifications hook created, fires success toast on complete, error toast on failed, skips initial load.</done>
</task>
