Refactor `fetchWithAuth` to accept a token-getter rather than a static token, so it can refresh:

```ts
type TokenGetter = (opts?: { skipCache?: boolean }) => Promise<string | null>;

export async function fetchWithAuth(
  path: string,
  getToken: TokenGetter,
  options: RequestInit = {}
): Promise<Response> {
  const doFetch = async (skipCache: boolean) => {
    const token = await getToken({ skipCache });
    return fetch(buildUrl(path), {
      ...options,
      headers: {
        ...options.headers,
        ...(token ? { Authorization: `Bearer ${token}` } : {}),
      },
    });
  };
  let res = await doFetch(false);
  if (res.status === 401) {
    res = await doFetch(true); // one retry with forced refresh
  }
  return res;
}
```

Update all call sites. `useApiToken()` hook should now return a `getToken` function bound to `useAuth().getToken`, not a pre-fetched string. Search-replace per `grep -rn "fetchWithAuth" frontend/src`.

Tests (Vitest, jsdom):
1. First call returns 200 → returned as-is (no retry).
2. First call returns 401, retry returns 200 → caller sees 200; `getToken` called twice (second with skipCache).
3. First call 401, retry 401 → caller sees 401 (no infinite loop).
4. Non-401 statuses (403, 500) → no retry.
5. `getToken` returns null → request goes without Authorization header (anonymous path); no retry on 401 (no token to refresh).

Mock `fetch` and `getToken` with vi.fn().
