```js
class PlaidTokenEncryptionService {
  constructor({ masterKeyHex } = {}) {
    const key = masterKeyHex || process.env.PLAID_ENCRYPTION_KEY;
    if (!key) throw new Error('PLAID_ENCRYPTION_KEY required');
    if (!/^[0-9a-fA-F]{64}$/.test(key)) throw new Error('PLAID_ENCRYPTION_KEY must be 32-byte hex');
    this.masterKey = Buffer.from(key, 'hex');
  }
  encryptForStorage(plaintext, userId) { /* existing logic, uses this.masterKey */ }
  decryptFromStorage(blob, userId) { /* existing logic, uses this.masterKey */ }
}

// Backward-compatible singleton
const defaultInstance = new PlaidTokenEncryptionService();
module.exports = {
  PlaidTokenEncryptionService,
  encryptForStorage: defaultInstance.encryptForStorage.bind(defaultInstance),
  decryptFromStorage: defaultInstance.decryptFromStorage.bind(defaultInstance),
};
```

Singleton wrappers preserve every existing call site without changes. New script will instantiate two instances (old key + new key).

<task type="auto">
  <name>Task 2: scripts/rotate-plaid-encryption-key.js with dry-run default</name>
  <files>backend-express/scripts/rotate-plaid-encryption-key.js, backend-express/__tests__/scripts/rotate-plaid-encryption-key.test.js</files>
  <action>
CLI script. Parse args with built-in `process.argv` (mirror `backfill-plaid-tokens.js` style):
- `--new-key <hex>` (required) — new 32-byte hex master key.
- `--apply` — actually write (without this, dry-run).
- `--target-version <N>` — only rotate rows WHERE `encryption_version < N`. Default = (max existing version) + 1.
- `--batch-size <N>` — default 100.

Flow:
1. Validate args. Refuse if `--new-key` matches `process.env.PLAID_ENCRYPTION_KEY` (no-op rotation).
2. Instantiate `oldSvc = new PlaidTokenEncryptionService()` (env key) and `newSvc = new PlaidTokenEncryptionService({ masterKeyHex: newKey })`.
3. Open Supabase service-role client (reuse pattern from backfill script).
4. Query `plaid_items` rows WHERE `encryption_version < targetVersion` AND `access_token_encrypted IS NOT NULL`, paginated by batch-size.
5. For each row:
   - Decrypt with oldSvc → plaintext.
   - Re-encrypt with newSvc → newBlob.
   - **Verify round-trip:** decrypt newBlob with newSvc, assert equality with plaintext. On mismatch → log error, push row to `failures[]`, continue to next row (don't write).
   - If `--apply`: UPDATE row SET access_token_encrypted = newBlob, encryption_version = targetVersion.
   - Emit `emitAuditEvent('plaid_key_rotated', { userId, itemId, fromVersion, toVersion })`.
6. Print summary: scanned, rotated, skipped, failed. Exit 0 only if failures.length === 0.
7. Log discipline mirrors backfill: counts + itemId + userId only. NEVER log plaintext token, blob, or key material.

Tests: Unit-test the row-rotation function with a mocked Supabase client. Cases:
1. Happy path: 3 rows, dry-run, no writes attempted, summary correct.
2. Happy path with --apply: 3 rows written, audit events emitted, exit 0.
3. Round-trip mismatch on one row: failure recorded, other rows still rotated (with --apply), exit non-zero.
4. Same-key rejection: throws before opening DB.
