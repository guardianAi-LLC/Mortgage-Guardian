  <name>Task 1: utils/auditEvent.js helper + instrument middleware/auth.js</name>
  <files>backend-express/utils/auditEvent.js, backend-express/middleware/auth.js, backend-express/__tests__/utils/auditEvent.test.js</files>
  <action>
**auditEvent.js:** Export `emitAuditEvent(eventName, payload)`. Internally:
- Validates `eventName` is a string from a frozen allow-list: `['session_started', 'session_ended', 'user_deleted', 'auth_failure', 'plaid_token_decrypted', 'plaid_token_encrypted', 'plaid_key_rotated']` (extensible by adding to the const).
- Calls `createLogger('audit').info(eventName, { event: eventName, ...payload, timestamp: new Date().toISOString() })`.
- Never logs `password`, `token`, `access_token`, `apiKey`, `secret` — strip any matching keys from `payload` before logging (defensive). Log a warn if stripped.
- Export the allow-list as `AUDIT_EVENTS` for callers.

**middleware/auth.js:** On every 401 path emit `emitAuditEvent('auth_failure', { reason, requestId, route: req.path, method: req.method })`. Reasons: `'missing_token'`, `'invalid_signature'`, `'expired_token'`, `'malformed_token'`, `'jwks_unavailable'`. Do not log the token itself. Existing 200/next paths untouched.

**Test:** Unit tests for `auditEvent.js` covering allow-list rejection, sensitive-key stripping, timestamp injection. Mock the logger.
  </action>

  <done>Helper exported with allow-list + sensitive-key scrub; auth.js emits `auth_failure` on all 401 paths with reason codes; tests green.</done>

<task type="auto">
  <name>Task 2: POST /v1/auth/clerk-webhook with svix signature verification</name>
  <files>backend-express/routes/auth.js, backend-express/utils/envValidator.js, backend-express/package.json, backend-express/__tests__/routes/auth-webhook.test.js</files>
  <action>
1. `npm --prefix backend-express install svix` — Clerk's recommended webhook verifier.
2. Add `CLERK_WEBHOOK_SECRET` to required env list in `envValidator.js` (required in production, optional in test/dev — follow existing pattern for `PLAID_ENCRYPTION_KEY` or similar).
3. New file `backend-express/routes/auth.js` exporting an Express router with `POST /clerk-webhook`:
   - Use `express.raw({ type: 'application/json' })` for this route only (svix needs raw bytes).
   - Verify signature with `new Webhook(process.env.CLERK_WEBHOOK_SECRET).verify(rawBody, headers)`. On failure → 401 + `emitAuditEvent('auth_failure', { reason: 'invalid_clerk_webhook_signature', requestId })`.
   - On valid payload, switch on `event.type`:
     - `'session.created'` → `emitAuditEvent('session_started', { userId: event.data.user_id, sessionId: event.data.id, requestId })`
     - `'session.ended'`, `'session.removed'`, `'session.revoked'` → `emitAuditEvent('session_ended', { userId: event.data.user_id, sessionId: event.data.id, reason: event.type, requestId })`
     - `'user.deleted'` → `emitAuditEvent('user_deleted', { userId: event.data.id, requestId })`
     - others → log info and return 200 (Clerk requires 200 to stop retries).
   - Always return 200 on valid signature.
4. Mount router in `server.js`: `app.use('/v1/auth', require('./routes/auth'))`. The CSRF Origin guard from 56-01 will exempt this route via bearer-bypass logic? No — webhook has no bearer. Add `/v1/auth/clerk-webhook` to `csrfOriginGuard` exemptPaths in `server.js`.
5. Tests: supertest cases for invalid signature → 401; valid signature with each event type → 200 + audit event emitted (spy on logger).
  </action>
  <verify>`npm --prefix backend-express test -- routes/auth-webhook.test.js --watchman=false` green; `node -e "require('./backend-express/routes/auth')"` loads; envValidator rejects missing `CLERK_WEBHOOK_SECRET` in NODE_ENV=production.</verify>
  <done>Webhook route mounted, signature-verified, emits session/user audit events; exempt from CSRF Origin guard; envValidator updated; svix dep installed.</done>
