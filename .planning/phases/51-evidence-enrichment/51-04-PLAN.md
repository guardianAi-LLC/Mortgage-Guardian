<task type="auto">
  <name>Task 1: Rebuild confidenceScoringService.buildEvidenceLinks() with real evidence</name>
  <files>backend-express/services/confidenceScoringService.js, backend-express/__tests__/services/confidenceScoringService.test.js</files>
  <action>
Replace the template-based evidence linking with real evidence from enriched findings.

**Current behavior (to replace):**
- buildEvidenceLinks() iterates over findings and creates evidence link objects with:
  - Template `evidenceDescription` like "Anomaly detected in field {field}"
  - `sourceDocumentIds` as array of document IDs only
- This produces generic, unhelpful evidence links

**New behavior:**
1. For each anomaly-type evidence link:
   - `sourceDocumentIds`: [anomaly.sourceDocument.id] (from enriched anomaly)
   - `sourceDocumentNames`: [anomaly.sourceDocument.name] (NEW — human-readable names)
   - `evidenceDescription`: Use anomaly.quotedText if available, fall back to anomaly.description. Prefix with document name and page: "[DocName, p.X]: {quotedText or description}"
   - `pageReferences`: [{ documentId, documentName, pageNumber }] from anomaly (NEW)
   - Keep existing fields: findingId, findingType, severity

2. For each discrepancy-type evidence link:
   - `sourceDocumentIds`: [discrepancy.documentA.documentId, discrepancy.documentB.documentId]
   - `sourceDocumentNames`: [discrepancy.documentA.documentName, discrepancy.documentB.documentName] (NEW)
   - `evidenceDescription`: Combine both sides: "[DocA, p.X]: {quotedTextA} vs [DocB, p.Y]: {quotedTextB}". Fall back to values if no quoted text.
   - `pageReferences`: Collect from both documents (NEW)

3. For each violation-type evidence link:
   - `sourceDocumentIds`: violation.sourceDocuments.map(d => d.id) (from enriched violation)
   - `sourceDocumentNames`: violation.sourceDocuments.map(d => d.name) (NEW)
   - `evidenceDescription`: Include violation.citation + first supporting finding's quotedText
   - `pageReferences`: violation.pageReferences (NEW — already assembled in Plan 03)
   - `supportingFindingIds`: violation.supportingFindings.map(f => f.findingId) (NEW)

**Backward compatibility:**
- If a finding lacks enriched evidence fields, fall back to the old template behavior
- Check for null/undefined before accessing enriched fields

**Test updates:**
- Update buildEvidenceLinks tests to provide enriched input data
- Add test case verifying real evidence descriptions (not templates)
- Add test case verifying backward compat with un-enriched input
- Verify sourceDocumentNames and pageReferences are populated
  </action>
  <verify>cd backend-express && npm test -- --testPathPattern="confidenceScoring" 2>&1 | tail -10</verify>
  <done>buildEvidenceLinks() produces evidence links with real quoted text, document names, and page references. Template fallback preserved for un-enriched data. All tests pass.</done>
</task>

<task type="auto">
  <name>Task 3: Update Joi schemas for enriched data structures</name>
  <files>backend-express/schemas/consolidatedReportSchema.js, backend-express/schemas/crossDocumentAnalysisSchema.js</files>
  <action>
Update Joi validation schemas to accept (but not require) the new evidence enrichment fields.

**consolidatedReportSchema.js changes:**
1. In the anomaly schema within documentAnalysis items:
   - Add optional fields: `pageReference` (Joi.number().integer().allow(null)), `quotedText` (Joi.string().max(500).allow(null)), `sourceDocument` (Joi.object({ id, name, type, subtype }).allow(null))

2. In the evidenceLinks schema:
   - Add optional: `sourceDocumentNames` (Joi.array().items(Joi.string())), `pageReferences` (Joi.array().items(Joi.object({ documentId, documentName, pageNumber }))), `supportingFindingIds` (Joi.array().items(Joi.string()))

3. In the violations schema (both federal and state):
   - Add optional: `sourceDocuments` (Joi.array().items(Joi.object({ id, name, type }))), `supportingFindings` (Joi.array().items(Joi.object({ findingId, findingType, quotedText }))), `pageReferences` (same structure as evidenceLinks)

**crossDocumentAnalysisSchema.js changes:**
4. In the discrepancy schema:
   - Extend documentA/documentB objects with optional: `documentName` (Joi.string()), `documentType` (Joi.string()), `pageNumber` (Joi.number().integer().allow(null)), `quotedText` (Joi.string().max(500).allow(null))

5. In timelineEvents/timelineViolations:
   - Add optional: `documentName` (Joi.string()), `relatedDocumentNames` (Joi.array().items(Joi.string()))

**Important:**
- All new fields MUST be optional (.allow(null) or not required) for backward compatibility
- Do NOT make any existing required fields optional
- Do NOT change the structure of existing required fields
- Run schema validation tests to confirm
