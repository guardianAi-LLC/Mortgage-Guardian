<task type="auto">
  <name>Task 1: Create evidence enrichment configuration</name>
  <files>backend-express/config/evidenceEnrichmentConfig.js</files>
  <action>
Create a new config file that defines the standard evidence enrichment fields used across all analysis services. This is the shared data contract.

Define:
1. `EVIDENCE_FIELDS` — the enrichment fields every finding should include:
   - `sourceDocument`: { id, name, type, subtype } — which document the finding came from
   - `pageReference`: number or null — page number where evidence was found
   - `quotedText`: string or null — exact quoted text supporting the finding (max 500 chars)
   - `quotedTextContext`: string or null — surrounding text for context (max 200 chars)

2. `DISCREPANCY_EVIDENCE_FIELDS` — enrichment for cross-document discrepancies:
   - Per-document: { documentId, documentName, documentType, field, value, pageReference, quotedText }

3. `VIOLATION_EVIDENCE_FIELDS` — enrichment for compliance violations:
   - `sourceDocuments`: [{ id, name, type }] — which documents triggered the violation
   - `supportingFindings`: [{ findingId, findingType, quotedText }] — anomalies/discrepancies supporting this violation
   - `pageReferences`: [{ documentId, documentName, pageNumber }]

4. `ENRICHMENT_PROMPT_INSTRUCTIONS` — reusable prompt fragments that tell Claude to include evidence metadata in its response. Define for:
   - `ANOMALY_EVIDENCE_INSTRUCTION`: "For each anomaly, include: pageNumber (integer, the page where found), quotedText (exact text from document supporting this finding, max 500 chars)"
   - `DISCREPANCY_EVIDENCE_INSTRUCTION`: "For each discrepancy per document, include: pageNumber (integer), quotedText (exact text from that document)"
   - `GENERAL_EVIDENCE_INSTRUCTION`: "Always cite specific values, dates, amounts directly from source text. Never make claims without quoting the source."

Use CommonJS module.exports. Follow existing config file patterns (e.g., consolidatedReportConfig.js). Keep it simple — constants only, no logic.
  </action>

   - Modify the expected JSON response structure to include these fields in each anomaly object
3. Add `GENERAL_EVIDENCE_INSTRUCTION` to the system prompt to enforce citation discipline

**Response parsing changes:**
4. In the response parsing logic (where anomalies are extracted from Claude's JSON response), capture the new fields:
   - `pageReference`: parsed from `pageNumber` in Claude's response (default null if missing)
   - `quotedText`: parsed from `quotedText` in Claude's response (default null if missing, truncate to 500 chars)

   - `sourceDocument`: { id: documentId, name: documentName or filename, type: documentType, subtype: documentSubtype }

- All new fields default to null if Claude doesn't provide them (graceful degradation)
- Existing anomaly fields (field, type, severity, description, expectedValue, actualValue) remain unchanged
- Do NOT break existing tests — new fields are additive

**What to avoid:**
- Do NOT change the Claude model or temperature settings
- Do NOT modify the classification logic or document type routing
- Do NOT alter the extractedData structure (dates, amounts, rates, etc.) — only anomalies get evidence enrichment in this plan
