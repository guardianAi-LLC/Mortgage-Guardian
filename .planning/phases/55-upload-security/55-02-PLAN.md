<feature>
  <name>malwareScanService.scanBuffer(buffer)</name>
  <files>backend-express/services/malwareScanService.js, backend-express/__tests__/services/malwareScanService.test.js</files>
  <behavior>
The function takes a Node `Buffer` and resolves to a verdict object, or rejects with `MalwareScanError`.

Contract:
- `scanBuffer(Buffer): Promise<{ scanned: true, clean: boolean, threats: string[], engine: 'cloudmersive' }>`
- Throws `TypeError` synchronously (before any HTTP call) when `buffer` is not a Node `Buffer`.
- Throws `MalwareScanError` (custom subclass of `Error` exported alongside) on:
  - Network failure / DNS error / TCP reset against `CLOUDMERSIVE_BASE_URL`
  - HTTP timeout (exceeds `CLOUDMERSIVE_TIMEOUT_MS`)
  - HTTP 5xx
  - HTTP 401 / 403 (bad or rotated API key) — message must indicate auth so ops can triage
  - HTTP 429 (over quota / rate-limited)
  - Response body that is not valid JSON or is missing `CleanResult`
  - Empty input buffer (see Case 5 rationale)

Cases the test file must cover (RED phase writes ALL of these first):

| # | Input | Expected | Live? |
|---|-------|----------|-------|
| 1 | Buffer of the EICAR test string | resolves; `clean === false`; `threats` non-empty array containing a string matching `/EICAR/i`; `scanned === true`; `engine === 'cloudmersive'` | Yes |
| 2 | Buffer of a small known-clean payload (e.g., `Buffer.from('clean pdf-like bytes')`) | resolves; `clean === true`; `threats === []`; `scanned === true`; `engine === 'cloudmersive'` | Yes |
| 3 | `CLOUDMERSIVE_BASE_URL` overridden to `http://127.0.0.1:1` (unreachable) | rejects with `MalwareScanError`; error message references connection/network; does NOT resolve as clean | No |
| 4 | `buffer` arg is not a Buffer (e.g., string, null, plain object) | rejects synchronously with a `TypeError` before any network call | No |
| 5 | Empty Buffer (0 bytes) | rejects with `MalwareScanError` | No |
| 6 | Mocked HTTP 401 response from Cloudmersive | rejects with `MalwareScanError` whose message indicates auth failure (matches `/auth|401|key/i`); does NOT resolve as clean | No |

Rationale for Case 5: Cloudmersive will accept and respond to an empty upload, but the verdict is uninformative ("clean" is vacuous). Returning that as `clean === true` would let an attacker round-trip a zero-byte file through the upload route and claim it was scanned. Fail closed.

Rationale for Case 6: The single most likely real-world failure mode in production is a rotated or expired API key. Without this test we'd be one silent fallthrough away from "scanned: true, clean: true" on an unauthenticated 401 response body.

Implementation guidance (GREEN phase, do NOT write before tests fail):
- Primary path: use `cloudmersive-virus-api-client`. Construct the API instance lazily on first call; configure `apiClient.basePath = cloudmersiveBaseUrl` and `apiClient.authentications.Apikey.apiKey = cloudmersiveApiKey`. Call `scanFile(buffer, callback)` and wrap the callback in a Promise.
- Alternate path (acceptable, document rationale): native `fetch` with `FormData` POSTing to `${baseUrl}/virus/scan/file`, `Apikey` header, `AbortSignal.timeout(cloudmersiveTimeoutMs)`. Parse `response.json()`, branch on `response.status`.
- Map Cloudmersive response to verdict:
  - `CleanResult === true` → `{ scanned: true, clean: true, threats: [], engine: 'cloudmersive' }`
  - `CleanResult === false` → `{ scanned: true, clean: false, threats: (FoundViruses || []).map(v => v.VirusName), engine: 'cloudmersive' }`
  - Missing/invalid `CleanResult` → throw `MalwareScanError('malformed cloudmersive response')`
- Catch ALL errors from the client/fetch and rethrow as `new MalwareScanError(message, { cause: originalError })`. Include the HTTP status (when known) in the message for triage — e.g., `'cloudmersive scan failed: HTTP 401 unauthorized'`.
- Logging via `createLogger('malware-scan')`. Log at info on entry (size only, never content), info on verdict (clean flag + threat count), error on rejection (error class + status). NEVER log buffer bytes or threat-vector content as a JSON field — mortgage docs.
  </behavior>
