  <files>backend-express/scripts/cloudmersive-health-check.js, backend-express/scripts/README.md</files>
  <action>
1. Create `backend-express/scripts/cloudmersive-health-check.js`:
   - Loads `dotenv` from `backend-express/.env` (matches Phase 54 backfill pattern).
   - Reads `CLOUDMERSIVE_API_KEY`, `CLOUDMERSIVE_BASE_URL` (default `https://api.cloudmersive.com`), `CLOUDMERSIVE_TIMEOUT_MS` (default 15000). Exits 2 if `CLOUDMERSIVE_API_KEY` is missing.
   - Performs three probes in order, each with the configured timeout:
     a. **Clean probe** — POST a small synthetic buffer (literal text `scan-health-check ping`) to `/virus/scan/file`. Expect HTTP 200 + `CleanResult: true`. Anything else → exit 1 with a single-line reason (HTTP code or `unexpected_clean_result`).
     b. **EICAR probe** — POST the EICAR test string to `/virus/scan/file`. Expect HTTP 200 + `CleanResult: false` and a non-empty `FoundViruses`. Anything else → exit 1 (`eicar_not_detected` or HTTP code).
     c. **Quota probe (best-effort)** — research a Cloudmersive endpoint that exposes remaining quota for the key (e.g. `/limit` or `/usage`). If found, call it and print remaining / cap. If no such endpoint exists or it returns non-200, log a single line `quota_probe: skipped (<reason>)` and continue — do NOT fail the script on the quota probe alone.
   - Logging discipline:
     - NEVER log the API key, the EICAR string, or the clean buffer body. Use the placeholder `<eicar-fixture>` if referencing the EICAR test.
     - Log only: timestamps (ISO 8601), HTTP status codes, latency ms per probe, the engine's response `CleanResult` field, and the quota numbers if available.
     - On failure, single-line reason — no stack traces unless `--debug` is passed.
   - Exit 0 only when: key present AND clean probe passes AND EICAR probe detects. Quota probe is informational.

2. Update `backend-express/scripts/README.md`:
   - Add a new section `## cloudmersive-health-check.js  (Phase 55-04)` mirroring the Phase 54 backfill section.
   - Document required env (`CLOUDMERSIVE_API_KEY`, optional `CLOUDMERSIVE_BASE_URL`, `CLOUDMERSIVE_TIMEOUT_MS`).
   - Usage block: `node scripts/cloudmersive-health-check.js` (and `--debug` for verbose).
   - Exit codes: `0` healthy, `1` reachable-but-failed, `2` missing required env.
   - When to run: post-deploy smoke, oncall page for "uploads returning 502", ad-hoc when rotating the API key.
   - Cross-link to the Cloudmersive ops doc created in Task 2.

Do NOT:
- Call Cloudmersive with anything other than these two synthetic buffers — no real user files, no fixtures from disk.
- Cache results or write any persistent state.
- Print the API key, the EICAR string, or full response bodies.
  </action>
