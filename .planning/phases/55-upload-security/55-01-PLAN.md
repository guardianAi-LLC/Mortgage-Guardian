**Replan note (2026-06-10):** The original 55-01 assumed Railway-deployed backend. Discovered during execution that backend-express deploys to Vercel only. Replanned to use Cloudmersive (55-RESEARCH.md fallback path) as the primary scan engine. Railway sidecar option deferred — could be a future Phase 56+ change if the third-party data path becomes a compliance issue.

**Established patterns:**
- Env vars flow to Vercel via `vercel env add` and surface inside the Express request handler at `process.env.X`.
- Phase 54 patterns: secrets land in Vercel dashboard, never in tracked files; `.env.example` documents the key name only.
- `backend-express/utils/fileValidation.js` keeps the `scanFileContent(buffer)` shim that future plans replace.

**Constraining decisions:**
- Decision (this plan, Task 1): Cloudmersive hosted API is the scan host. ClamAV-on-Railway path is parked.
- 55-CONTEXT.md essential: real detection, sync feel on happy path. Cloudmersive sync endpoint adds ~200–800 ms.
- 55-RESEARCH.md pitfall #1: scan errors must NOT be silently treated as clean. Cloudmersive returns HTTP errors on overage / 5xx — those translate to MalwareScanError, not "clean."
- Cloudmersive free tier: 800 calls/month. Treat free tier as dev/staging only; production needs the paid plan before we cut over.

**Out of scope (per 55-CONTEXT.md):**
- Backend migration to Railway (separate future phase if ever).
- Application code changes — those land in 55-02 and 55-03.
- Retroactive scans, per-tenant scan policy, content moderation.

<task type="auto">
  <name>Task 2: Wire CLOUDMERSIVE env into project, .env.example, and Vercel envs</name>
  <files>backend-express/.env.example, backend-express/utils/envValidator.js</files>
  <action>
1. In `backend-express/.env.example`, add a `# Malware scanning` block with three keys, default values empty, with comments:
   - `CLOUDMERSIVE_API_KEY=` — the key from Task 1.
   - `CLOUDMERSIVE_BASE_URL=https://api.cloudmersive.com` — default; left settable for testing.
   - `CLOUDMERSIVE_TIMEOUT_MS=15000` — sync HTTP timeout. Cloudmersive sync calls are typically <1 s, 15 s is the hard ceiling before we 502 the upload.

2. In `backend-express/utils/envValidator.js`, add the three keys to the Joi schema (`Joi.string().optional().allow('')` for the key + base URL, `Joi.number().integer().min(1000).default(15000)` for timeout). Add a featureWarning when `CLOUDMERSIVE_API_KEY` is empty: "CLOUDMERSIVE_API_KEY missing — upload scanning will fail closed." Export the three on the validated config object (`cloudmersiveApiKey`, `cloudmersiveBaseUrl`, `cloudmersiveTimeoutMs`).

3. Verify Vercel env presence (do NOT touch the key value in chat or in files):
   - `cd backend-express && vercel env ls 2>&1 | grep -i cloudmersive` — should show entries for Development / Preview / Production (or whichever scopes the user said they set in Task 1).
   - If `vercel` CLI is not authenticated, surface as a dynamic auth gate (`vercel login`) and retry. Do NOT proceed past this verification.

Do NOT:
- Write the API key to any tracked file. `.env.example` documents the key NAME only.
- Hard-code `https://api.cloudmersive.com` in service code — read from `CLOUDMERSIVE_BASE_URL` so the value can be overridden in tests.
- Skip the timeout. A missing client timeout means a hung Cloudmersive call holds the Vercel function until its own 10–60 s plan timeout — that becomes a user-visible upload hang.
  </action>

  <how-to-verify>
End-to-end live-fire from the deployed Vercel API (NOT from local) to prove the key works and EICAR is detected by Cloudmersive:

1. From any shell with the prod `CLOUDMERSIVE_API_KEY` in env (do NOT paste it in chat):
   ```
   EICAR='X5O!P%@AP[4\PZX54(P^)7CC)7}$EICAR-STANDARD-ANTIVIRUS-TEST-FILE!$H+H*'
   curl -X POST https://api.cloudmersive.com/virus/scan/file \
     -H "Apikey: $CLOUDMERSIVE_API_KEY" \
     -F "inputFile=@-" <<< "$EICAR" | tee /tmp/eicar-scan.json
   ```
   Expect JSON containing `"CleanResult": false` and a `FoundViruses` entry referencing EICAR.

2. Clean buffer:
   ```
   echo "this is a clean test buffer" | curl -X POST https://api.cloudmersive.com/virus/scan/file \
     -H "Apikey: $CLOUDMERSIVE_API_KEY" \
     -F "inputFile=@-"
   ```
   Expect `"CleanResult": true`.

3. (Optional but recommended) Confirm the Cloudmersive dashboard shows your two test calls under "Usage" within a few minutes — proves the key is the one actually being used.
  </how-to-verify>
