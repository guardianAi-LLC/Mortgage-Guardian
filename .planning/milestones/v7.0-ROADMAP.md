**Status:** SHIPPED 2026-04-19

## Overview

Complete the Next.js web dashboard as the browser counterpart to the iOS app — wire existing UI components to the Express backend, add analytics visualizations, Plaid bank linking, and deploy to production.

**Key results:** Full-featured web dashboard deployed to Vercel (frontend-guardianai-llc.vercel.app). Document management with batch operations, analytics with 6 Recharts visualizations, Plaid bank integration, real-time pipeline notifications, global search, dark/light theme, WCAG accessibility, 76 Playwright E2E tests, SEO optimization, Sentry monitoring, Supabase SSR integration.

## Milestone Summary

**Key Decisions:**

- Next.js API route rewrites for Express proxy (no separate CORS domain)
- Clerk JWT auth with Supabase fallback (dual-provider middleware)
- Client-side filtering with limit=500 fetch (vs server-side pagination)
- react-plaid-link with localStorage access token storage
- sonner for toast notifications (vs react-hot-toast)
- next-themes for dark/light toggle with CSS variables
- Playwright with @clerk/testing for E2E (vs Cypress)
- Dynamic imports for Recharts and react-plaid-link (bundle optimization)
- Supabase SSR integration for Vercel deployment
- --legacy-peer-deps for React 19 compatibility

**Issues Resolved:**

- Clerk JWT auth token format (removed Supabase template token)
- snake_case/camelCase response mapping across all API responses
- React 19 peer dependency conflicts with react-plaid-link and Playwright
- Clerk signIn TypeScript error in E2E fixtures
- Pre-existing Clerk @clerk/nextjs version incompatibility (upgraded 6.34.5 to 6.39.1)

**Issues Deferred:**

- None

**Technical Debt Incurred:**

- --legacy-peer-deps required for React 19 (react-plaid-link, @clerk/testing)
- Client-side filtering with 500-document limit (server-side pagination needed at scale)
- localStorage for Plaid access tokens (should migrate to secure server-side storage)
